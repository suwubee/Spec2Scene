# 审核与打回

先记录被审核提交和环境，再按 SPEC 编号逐项验证。复跑单测与浏览器流程；对识别算法再跑真实图片或抽帧视频。核对人工标注、解剖学左右手、峰值/起始时间口径及一对一匹配，调参与验收同集必须披露。

看截图：桌面、笔记本、窄手机；开始、加载、站位、游戏、暂停、错误、结算；角色正面/侧面/四分之三、峰值前后序列和转台。遮挡和动作轨迹不可只凭某个关节点断言。

量化：指定画面 ROI 的 CIE L*，文字 WCAG 相对亮度对比度、角色亮暗背景差异、按钮与声音门/预览/轨道的包围盒相交。全屏平均亮度会被黑边或留白污染，应同时报告 ROI 与整屏。

打回用 templates/REVIEW.md：严重度、现象、复现、证据、根因假说、目标、文件边界和复验。保留通过项，避免反复改方向。审核通过只针对所列环境与功能，真机、商用许可和生产验证另记。

## 音乐视频三道强制关卡

音乐视频采用 G1 意境与分镜 → G2 角色与表演 → G3 成片预览。每关必须由独立审核人（另一个会话或人类）完成；实现者自审不算。自动测试通过也不代表审美通过。没有上一关 PASS 不制作下一关，打回后保留失败截图并复验。

G1 检查意境书、意象转译表、色彩脚本、完整分镜和每段气氛样张；静音去字幕后应仍能感到情绪，重点拒绝逐句图解。G2 复跑人体约束测试，逐张查看八方向转台与关键动作序列，确认重心、关节方向与手部。G3 查看整曲联系表、每段关键帧、至少三段连续帧，记录实时性能，并按 music-video/directing/05-quality-bar.md 逐条评分。

审核人还必须亲自复跑 [picture-qa](../tools/picture-qa/README.md)（`npm run qa:picture`，修复轮加 `--compare <上一轮> --claim <检查项>`），逐条核对配置里的豁免理由（`sky`、`allowStripes`、`skip`+`skipWhy`）；实现者交来的“已修复”若没有 ⑥ 显示问题区域确实变化的报告，一律按未修复打回。picture-qa PASS 只排除七类已知错误，不代签审美，见[画面关卡](14-picture-gate.md)。

记录用 [音乐视频专用模板](../templates/REVIEW-music-video.md)，每条为“问题 → 证据截图路径 → 要求”。记录检查器 `tools/review-gates.mjs` 会拒绝自审、缺前置关卡或旧版本，但不能代替审核人亲自检查。工程工具库升级可交付待审代码与证据；未签署的样片关卡必须如实保持 PENDING，不能借库的单测绿灯声称成片获批。

## 标杆并排与审核误判

审核“通过”必须先和标杆比过。英雄镜头的 AD 评审与 G3 审核要填 [AD-review](../templates/AD-review.md) 的“标杆帧并排对照”：已批准标杆作品的同类参考帧与本作帧放进同一张图，逐列写细节密度（可辨构件数）、层次、光、材质、人物和判定；可数的写数字。没有并排表的 PASS 无效。只看意境、分镜、人体与字幕而不问“像不像一张电影剧照、道具够不够密”，是审核放水的典型来源。

用户否决了审核判过 PASS 的东西时，返工之前先在 [DIRECTOR-DECISIONS](../templates/DIRECTOR-DECISIONS.md) 写一条“审核误判记录”：审核人判 PASS 的内容与证据、用户看到的问题（原话与镜头时间）、缺了哪项检查、现在由哪个新增检查或阈值覆盖（工具、模板栏目或看图要求，写明位置）。没有落到新检查的记录不算完成；同类误判第二次出现时，先补检查再继续审核。审核结论还要附设计与代码的硬门槛：`npm run qa:brief`（设计深度）、`npm run qa:reimplement`（引擎能力未重写）、`npm run qa:camera`（相机稳定）。
