# 规格先行

使用 templates/SPEC.md，保留当前用户原话，匿名经验只作约束来源。一次明确：代码与生成素材边界、是否允许转录、音乐/地图/模型来源、署名与片尾、交付格式、设备、性能、预算、可访问性和部署权限。

按“触发→旧行为→目标行为→验收”写每一条。每项必须有编号、归属文件、接口、输入单位、坐标/镜像约定、错误与降级、验收方法。写清不做什么和允许的技术取舍；变更范围先更新规格再实现。

UI 不写抽象的‘好看’：约定视口、字体、主角占比、亮度 ROI、文字对比度、按钮最小尺寸、轨道保护区、零重叠规则。把音符几何与难度分开，声音状态与静音开关分开，缓存与初始化分开。

并行接口先列数据结构与生命周期，再决定目录归属。验收清单包括旧行为回归、负例、边界及缺少真实数据时的 SKIP，避免实现者为通过而改变标准。
