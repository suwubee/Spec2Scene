# 实时播放不能由截图验收替代

| 现象 | 根因 | 修复 | 预防 |
|---|---|---|---|
| 离线截图精细，用户点击后画面卡住且没有声音 | 作品播放器只保留确定性逐帧渲染；绑定按钮前构建场景，或点击先等待渲染准备 | 无依赖入口先绑定按钮，可信点击栈中同步调用 media.play；场景和编译交给 Worker | 生成器默认带实时层；审核人亲自在实时页点击，测按钮可用和解码起点 |
| 画面慢，音乐也跟着停顿 | 时间由渲染完成推进，或每帧等待补足历史采样 | 以媒体 currentTime 为主时钟，单帧在途，完成后读最新时间 | 用 20 秒墙钟测音频 19.6–20.4 秒，保持 playbackRate=1 |
| HUD 0 fps、虚高或一直不变 | 计数点在首次渲染前、RAF 请求处，或仅取 CPU 提交耗时倒数 | 在 GPU fence 完成、位图交付后计数；观察窗口分母包括等待 | 留存逐帧数据、显示暂停/测量中；截图和实时路径分开 |
| 自动档来回切，低档仍付全电影成本 | 单帧阈值无迟滞，参数变化没有真正降低阴影、几何和后期开销 | p90 窗口、冷却、慢档回升禁入；实时预览使用匹配预算的场景与 HDR 合成 | 实测降档后的交付帧率；保留低档审图，不能只改标签 |
| compileAsync 仍冻结界面 | 驱动缺并行编译扩展，或场景工厂本身有长同步任务 | 所有三维构建进 Worker；按镜头提前有限预热 | 记录扩展能力和冷启动；不将软件回退称为硬件编译通过 |
| 慢网播放按钮失效，首声数字看似全绿 | 按钮等待音乐/字体/场景；测试自带静音或宽松自动播放参数 | 按钮始终可用、缓冲比例可见、待播请求可取消；默认策略与未静音浏览器实测 | 慢网和弱机各一次；解码信号、网络等待、真人听审分别记录 |

仓库只回填方法、参数化工具、生成器和通用回归。作品、原始审核报告、实际音频与截图留在项目或临时证据目录。自动回归不代签独立“实时可看”关卡。

## 实时播放四条铁律

外部性能根因分析 `PERF_V32` 提炼出：自动降档销毁引擎会导致慢帧→降档→重新建场/编译→更慢的循环；逐镜建毁变体和播放中懒建会让驱动反复编译，compileAsync 本身不保证首次 draw 的材质、阴影和后期组合已编译。这里只保留因果，不收录原报告。

1. **换档永不重建引擎，不改 shader defines。** 运行时只调分辨率、drawRange/实例数、uniform 或跳过 pass；MSAA 固定。比较引擎/renderer 身份、材质 defines 和程序身份，不能只比较 programs.length（删除旧程序再建同数量也应报警）。
2. **预热后场景常驻。** 所有场景与变体一次创建，compileAsync 后逐镜代表时刻真实渲染，把阴影、反射、后期也预热。显存预算若不允许常驻，必须证明播放中仍不产生新程序。
3. **播放中零新程序编译。** 暖机期和播放期分开计数，记录 renderer.info.programs 的存量和新出现身份；整曲或逐镜 seek 复验，换档单独检查。
4. **固定灯光布局。** three 的程序键包含方向光、点光、聚光和半球光的数量以及投影灯数量。室内和室外分别声明固定的灯光预算，场景挂上强度为 0 的占位灯，播放时只改真实灯的强度、位置和可见性；不能因为一个镜头暂时没有灯就从数组移除它，也不能在暖机后添加新灯。`tracks/music-video/player/fixed-lights.js` 提供通用辅助，预算溢出应在暖机时失败并修正。

同机同后端比较实时性能时，使用“参考作品基准对比法”（以一部已验证流畅的成熟作品作基准）：固定 1280×720、浏览器后端、CPU/栅格线程和音频窗口，在两页都完成预热后测预热程序数、预热耗时、相邻 GPU 完成帧时间平均值/p90，并单列播放期长任务（>200 ms）。截图、解码波形和软件后端只能作为证据，不能替代目标 GPU、真人听审或独立审美审核。

v0.4.3 已把单引擎常驻、后台预热、运行时 RT resize、固定灯光签名和暖机后零新程序检查接入通用播放器；浏览器回归仍只证明软件后端与起步样片，不能代替目标设备的真人实时审核。

English: never rebuild on quality changes or change shader defines; keep warmed sets resident; observe zero new program identities during playback. Diagnostics are evidence, not a residency implementation.

## v0.5 默认选择

以上 Worker/分层方案保留为实验性，默认不用。新项目默认[点击逐镜预热与常驻](../../tracks/music-video/realtime/README.md)。用户同机实测优先于架构推断；历史重建/灯数组合修复不免除懒建和分层复杂度的回归风险。见[无声与闪烁教训](v05-playback-and-flicker.md)。
