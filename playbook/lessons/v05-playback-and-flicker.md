# 坚持已验证的播放栈与可辨认的新世界

| 现象 | 根因 | 修复 | 预防 |
|---|---|---|---|
| 新版在用户设备上几乎无法播放，成熟作品同机流畅 | 架构复杂度增加；换档重建、播放中懒建、不同灯数组合令程序数膨胀；后两轮修复部分机制也不能证明整个分层调度可靠 | 默认回到点击→逐镜真实预热→常驻场景→音频驱动画面；原分层播放器降为实验选项 | 坚持已验证的技术栈；任何替换先通过同机用户实测对比 |
| 软件测试全绿，用户仍认为播放差 | 把截图、平均 CPU 提交时间或另一台机器的数据当成体验证据 | 同一台机器、浏览器、后端、窗口尺寸和音源条件打开成熟作品与新作品；各自冷启动、点击、等预热、播放和切镜 | 记录点击响应、预热耗时、声音、卡顿时间码、稳定帧时和新程序；顺序交换复测，真人结论单列 |
| 慢网画面在走，声音永久消失 | 给音源探测设短超时，超时换源，最后静默退到墙钟 | 只在媒体 error 换源，无时间失败；点击同步解锁；预热后播放；就绪时对齐音频接管 | 严格用户激活、去 webdriver 特征、5 秒/25 秒延迟验证最终解码信号、同步及可见状态 |
| 新片与旧作品重合太多 | 复用了整套场景、标志道具组合和机位 | 先建立新的世界观、禁用清单；底层通用构件改型改色 | AD 评审 1 先查禁用清单，再查光照和细节 |

v0.4 分层播放器已修复过换档重建和灯数组合问题，并补了常驻与预热监控。这些工程修复应保留，但历史懒建路径、预览/完整场景分层、Worker 调度与质量策略的复杂度仍有回归风险，不能由日志推导成用户流畅体验；默认入口因此使用更直接的成熟流程。

## 闪烁七类原因

| 类别 | 观察与根因 | 修复与复验 |
|---|---|---|
| 1. 硬切世界跳变 | 实时时间落入切点附近的世界状态跳变窗口，子帧快门跨界 | 实时 cutSafe 保留左右归属并推到窗口边缘；±1/4.5/25 ms 复验，离线 seek 保持原值 |
| 2. 重映射帧中心错误 | 把预设时间四舍五入成帧中心，或用常量偏移近似逆映射，首帧采到上一镜世界 | 从真实 frame/fps 映射帧中心，world.at 用精确逆映射；覆盖拉伸、倒放、冻结与切点首帧 |
| 3. 粒子逐帧随机 | 近镜散景或雨滴每帧重抽位置，且未乘天气强度 | 固定种子和连续轨迹；按雨量/透明度调制；同帧逆序与连续序列检查 |
| 4. 近镜虚焦高光 | 贴镜粒子和水面反射产生巨大亮斑，阈值进出时闪跳 | 限定近镜范围、平滑淡出并约束散景能量；分块局部 spike 查看亮斑来源 |
| 5. 道具事件与镜头错位 | 发光物在切点前提前熄灭，动作/灯光使用了错误时间窗 | 校准事件时钟和镜头覆盖，逐帧看切前后及重映射边界 |
| 6. 火焰噪声频率过高 | 多八度高频噪声超过运动和采样预算 | 约束最高频率（例如 ≤4 Hz）、幅度与音符耦合；24/60 Hz 双路检测 |
| 7. 材质缝光噪声过快 | 细缝或窄高光的高频亮度调制混叠 | 限制频率（例如 ≤3 Hz），必要时改善空间抗锯齿；局部连续帧检查 |

工具以 64×36 相邻差 spike/step 与 16×9 分块局部 spike 给候选，不能自动判定艺术意图。设计颗粒、快速摇镜、正常硬切都可能触发；在 flags 旁记录人工解释与连续帧，修复后保留旧轮并重新检测。
