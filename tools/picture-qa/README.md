# picture-qa：画面自动质检（强制关卡）

`picture-qa` 是音乐视频与三维场景的**画面硬门槛**：每一版、每个镜头的代表帧在交给导演或审核人之前必须全部 PASS；任何“已修复”的声明必须附 `--compare <上一版> --claim <检查项>` 的结果，否则视为未修复。

它只做像素统计（纯 JS，只依赖 `node:zlib`），不调用任何模型，也不需要“会看图”。同一组 PNG 在任何机器上得到同一份 JSON 与同一个 PASS/FAIL。所以**任何模型都能跑、都能读懂结果**：报告给出失败检查名、数值和问题区域坐标（`box` 归一化、`px` 原图像素），不会看图的模型也能据此定位要改的区域；会看图的模型和人再看 `<帧>_qa.png` 标注图。

它不代替独立视觉审核：PASS 只说明“这七类已知错误没有出现”，不说明画面好看、构图正确或符合意境。导演/审核人仍逐图签字。

## 用法

```bash
# 仓库内
node tools/picture-qa/picture-qa.mjs --selftest                        # 合成回归样本（npm test 也会跑）
# 生成项目内（scripts 已写好）
npm run qa:picture -- --dir out/review/<scene>/r03                      # 逐帧质检，逐镜配置 docs/picture-qa.shots.json
npm run qa:picture -- --url http://127.0.0.1:39920/?mode=capture --scene exterior --t 4,12.5,19
npm run qa:picture -- --dir out/review/<scene>/r04 --compare out/review/<scene>/r03 --claim stripes,halo
npm run qa:picture -- --check-config docs/picture-qa.shots.json        # 只校验配置，列出全部豁免
npm run qa:picture -- --check-config docs/picture-qa.shots.json --baseline <上一版配置>   # 变宽即 ALERT，退出码 4
```

输出（`--out`，默认 `out/picture-qa/<时间>/`）：每帧的豁免与配置告警（`exemptions`、`configWarnings`、`skyAudit`）一并写入；`report.json`（机器可读）、`report.md`（表格 + 每个 FAIL 的区域与数值）、`<帧>_qa.png`（标注图）、`<帧>_diff.png`（与上一版的 |ΔY|×8 热图）、`sheet.png`（全部标注图联系表）。退出码：0 全部 PASS，1 有 FAIL，2 用法/读图/抓帧/配置错误，3 selftest 不符合预期，4 配置相对 `--baseline` 变宽。

`report.json` 结构：`results[i] = {file, shot, pass, failed:[检查名], checks:{<检查>:{pass, 数值…, regions|worst|blobs|problems:[{box, px}]}}}`。模型的修复循环应该是：读 `failed` → 读该检查的区域 `px` → 改代码 → 重新出同名帧 → `--compare 上一版 --claim <这些检查>` → 全部 PASS 才汇报。

## 七项检查：检查什么、为什么、怎么算、阈值、误报

所有检查在“裁掉黑边、面积重采样到 960 宽”的画面上进行；亮度 Y = 0.2126R′+0.7152G′+0.0722B′（编码值 0..1）。阈值常量在 `picture-qa.mjs` 的 `TH`，全部由 `samples.json` 的回归样本锁定。

| 检查 | 抓什么（为什么要抓） | 算法 | FAIL 条件 | 误报情形与对策 |
|---|---|---|---|---|
| ① stripes 条纹/各向异性 | UV 或 xz 平面投影在竖面/斜面上拉伸成竖条纹墙；沿风长条噪声在透视下汇聚成放射条纹；长焦掠射把地面细起伏压成“岩层/木板”横带；噪声瓦片重复。模型常把这类问题误判为“风纹强度/颜色”去调参数，画面不变 | Y 去 25 px 低频；96 px 瓦片（步长 48）对 24 个方向求“沿该方向平均后的一维剖面”方差。条纹瓦片 = 最强方向/中位数 ≥ 6、剖面幅度 ≥ 0.0035、占瓦片方差 ≥ 0.12、零交叉 ≥ 6（≥3 条线）、**长直**（沿条纹方向切两半，两半剖面相关 ≥ 0.75）；近水平（±12°）须幅度 ≥ 0.013 | 条纹瓦片面积 ≥ 10% 或最大连通区 ≥ 6%（给了 roi 时 roi 内 ≥ 25%） | 有意的规则纹理（版筑层、百叶、栏杆、瓦垄）在配置 `allowStripes` 框出并写 `why`，总面积 ≤ 35%，超出直接报配置错误。建筑边线（2–4 条线、相关低）不计；透视压缩的弱横纹不计 |
| ② halo 外缘光晕 | 人物或暗物体外缘一圈白描边（遮罩与主画面错位、轮廓光过宽过强），像抠图 | 白顶帽 = Yb − 开运算(Yb, 7×7)；候选 = 顶帽 > 0.03 且 Y > 0.05 且 11×11 内最暗 < 0.5·Y；8 连通；保留 ≥ 30 px、外接框长边 ≥ 18 px、填充率 ≤ 0.4、梯度方向覆盖 ≥ 3/4 个方向桶（闭合轮廓） | 任一光晕 n ≥ 80 px 且平均顶帽 ≥ 0.045 | 直线亮檐口、雪檐（单一方向）不计；灯具小亮团不计；1–2 px 低强度冷轮廓不计 |
| ③ flat 大面积平涂 | 无材质的平面多边形、平涂黑块/灰块（“墙是黑块”“远山是色块”） | 4×4 盒降采样 + 3×3 盒（压掉胶片颗粒）；每 16 px 块取 32 px 窗做**平面拟合**，残差 σ < 0.0011 为平涂；天空除外；8 连通 | 最大连通区 ≥ 10% 或总面积 ≥ 18% | 纯天空构图（仰拍）没有地平线，自动天空认不出 → 配置 `sky:{rects:[…]}`；全帧灰雾也会触发（同时 ④ FAIL） |
| ④ luma 亮度分布 | 全帧灰雾、没有最亮处/最暗处、曝光出逐镜亮度带 | 全帧 Y 排序：mean、p01、p05、p50、p95、p99、p999，DR = p99 − p01 | mean ∉ [lo,hi]；p99 < p99min（默认 0.20）；p01 > p01max（0.10）；DR < drmin（0.15） | 逐镜亮度带写进配置；近黑开场、雾景等特殊镜头单独配置并写理由 |
| ⑤ clouds 积云团 | 晴夜天空里的卡通积云团 | 天空：先找**横贯画面的地平线**（逐行上下块均值差的列中位数最大且 ≥ 0.012、≥ 50% 列同号），没有 → 不认天空；有 → 只在地平线以上从上沿漫延平滑块（多档 σ/跳变由松到紧）。背景 = 天空带内 ±4 行 ±6 列中位数；亮团 = 均值 − 背景 > 0.014 的连通块 | ≥ 4 块（≈0.25% 画面）、≥ 40% 在平滑天空内、长宽比 ≤ 5（细长 = 卷云，允许）、不含 > 0.85 的亮核（月/灯） | 地平线辉光、月晕被中位数背景吃掉。已知误报：街巷（墙/街交界像地平线）、仰拍纯天空、远山雪线高出地平线 → 配置 `sky:"none"` 或 `sky.rects` |
| ⑥ diff 对比上一版 | “汇报已修复但画面没变”：改了不生效的参数、改错文件、程序缓存键相同导致新代码从未执行、只改了别处 | 两版 Y（3×3）逐像素 \|Δ\|，变化像素 = \|Δ\| > 4/255；对上一版每个失败区域及 roi 求区域内变化比例 | 声称修复的项（`--claim`/配置 `claim`/roi）问题区域变化 < 2% 或均差 < 0.6/255；`--claim` 点名的检查在上一版没有检出问题且没给 roi（无法核实）；给了 `--require-change` 且无 claim 时全帧变化 < 2% | 未声称的旧问题列为 open，不判 FAIL（但其自身检查照常 FAIL）；只比较同名（同 t）帧；尺寸不同直接 FAIL |
| ⑦ warm 暖色占比 | 夜景暖色泛滥，“一点暖”失控 | 暖像素 = max > 0.05 且 R − B > 0.04 且饱和度 > 0.25 且 R ≥ 0.85G；统计占比与 16 px 暖区 | 占比 > warmMax（内置 0.10，模板默认 0.05） | 拂晓、灯下特写在配置中放宽并写理由 |

`--claim` 必须与 `--compare` 同时出现，单独使用是用法错误（退出码 2）。`skip` 跳过某项检查必须同时写 `skipWhy`；所有豁免都会原样写进 report.json，审核可见。不允许用豁免绕过正在修的问题。

## 逐镜配置

模板：[shots.template.json](shots.template.json)。生成项目把它放在 `docs/picture-qa.shots.json`，由场景负责人维护自己镜头的条目。帧 → 镜头按文件名匹配：`<scene>_t<秒>.png`（`--url --scene ID` 抓帧的命名）、`t<秒>.png` 或 `frame-<n>.png` + `fps`；`t ∈ [t0, t1)`。合并顺序：内置 TH < defaults < scene < shot < 命令行。字段：`luma{lo,hi,p99min,p01max,drmin}`、`warmMax`、`sky`、`allowStripes[{rect,why}]`、`roi`、`claim`、`requireChange`、`skip`+`skipWhy`、`exempt`、`notes`；`_` 开头的键是注释，但 `_why` 在有豁免的层是必填的。未知键、越界矩形、缺 `exempt`/`_why` 的豁免都会让 `--check-config` 失败（见下节）。

## 豁免的唯一依据与配置报警（v0.8）

豁免只能建立在画面里的三类事实上，每条都必须在**同一层**写 `"exempt": [...]` 与 `"_why"`（≥ 12 字，说清画面里是什么）：

| `exempt` | 可以豁免什么 | 例子 |
|---|---|---|
| `designed-texture` | `allowStripes`（只能用它）、`skip`、`warmMax` 提高、亮度阈值 | 夯土层理、搭接船板、窗棂、瓦垄；暖色木作 |
| `real-light` | `warmMax` 提高、`skip`（如 halo）、亮度阈值（p99min/drmin 等） | 灯芯 bloom、只剩一点灯的物理亮度地板、拂晓低日 |
| `non-sky-region` | `sky`（`none` / 比例 / `rects`，只能用它）、`skip` | 远山雪线、街巷墙顶、俯视无天空、仰拍纯天空 |

- “比模板默认更宽松”的任何值都算豁免：`warmMax` > 0.05、`luma.lo` < 0.03、`hi` > 0.45、`p99min` < 0.20、`p01max` > 0.10、`drmin` < 0.15、任何 `sky` 声明、任何 `skip`、任何 `allowStripes`。更严格的值（窄亮度带、更低 warmMax）不是豁免。
- 不能豁免的：`requireChange` 低于 0.02（放宽“修复核实”）、`skip: ["diff"]`。这两项写进配置直接校验失败。
- `--check-config` 逐条列出全部豁免（`EXEMPT …`，含模板默认值与 `_why`），report.json 的 `results[i].exemptions` 与 report.md 末尾“Exemptions and config warnings”原样列出，审核人逐条看。
- **配置变更报警**：`--check-config new.json --baseline old.json` 对每个镜头比较合并后的有效配置；天空掩码面积缩小（或由自动天空改为声明天空）、任何阈值变宽、新增 skip、`allowStripes` 面积变大、`requireChange` 变小，逐条打印 `ALERT` 并以退出码 4 结束。原则：画面没变而配置变宽，就是“为通过而改配置”；要么改画面，要么由导演逐条签字。
- **天空掩码审计**：声明了 `sky` 的帧同时计算自动天空；声明的天空比自动天空少掉 > 2% 画面时写 `configWarnings`（“sky mask shrunk”），若 ⑤ 只在声明掩码下 PASS、用自动天空会 FAIL，`clouds.maskedByConfig = true` 并告警。缩小天空掩码去躲积云检测是实际出现过的做法；告警不判 FAIL（远山雪线等真非天空区域也会触发），但必须在 GATE 里逐条解释。

## 回归样本（合成，不含任何作品帧）

[samples.json](samples.json) 用 [synth.mjs](synth.mjs) 的声明式图层（地面噪声、渐变天空、条纹、平涂块、剪影与光环、云团、卷云、雾、暖色区）程序生成每一帧，仓库不存任何图片。每项检查都有 FAIL 与 PASS 样本，⑥ 覆盖“声称修复且变了 / 完全没变 / 只改了别处 / 无法核实的声明 / roi 兜底 / 必须有变化 / 未声称的旧问题”。`npm test` 通过 `tools/test/picture-qa.test.mjs` 跑全部期望、确定性（两次运行 JSON 相同）与配置校验。

改阈值或算法的规则：先加能复现新问题（或新误报）的合成样本，再改代码；selftest 必须全绿；在 lessons 里写明原因。不得为了让某个作品帧通过而放宽阈值，作品特例写进该镜头的配置并附理由。

## 起步样片的结果（不是通过关卡的例子）

生成项目自带的 60 秒程序化样片用默认配置跑 `--url …?mode=capture --scene sample --t 4,40` 时会 FAIL：雪夜段脚印口沿亮、印底暗，构成闭合亮轮廓（② halo，属于“印底应压暗、口沿不应盛光”的真实问题），月旁光柱与云被判为亮团（⑤）；站台段灯光是设计出的暖色（⑦，需在配置中放宽并写理由），雨丝与长椅条板出现条纹（①）。样片只用于验证工具链，替换为作品镜头后按本页配置逐镜处理；不要把样片当作已通过关卡的参照。

## 已知局限（如实记录）

1. 对低对比（剖面幅度 < 0.0035）的放射/长条纹不敏感——用 ⑥ `--compare` + `roi` 兜底，并要求人工复核。
2. 近水平带须幅度 ≥ 0.013 才计（地面透视压缩天然有横纹），低幅“岩层”同样靠 ⑥ + roi 拦截。
3. ⑤ 的自动天空依赖横贯画面的地平线；复杂构图请在配置里写 `sky`。
4. 只看单帧统计：闪烁用 `tools/flicker-check.mjs`，确定性用复渲比对，构图/意境/表演仍由独立审核判断。
5. 阈值按 960 宽标定，输入任何尺寸都会先缩放；极小的画面（< 480 宽）细节会丢失。
