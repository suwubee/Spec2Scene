# 任务派发骨架

阅读当前项目 SPEC.md 全文、AGENTS.md、对应产线 README/lessons，以及本轮 REVIEW。实现 <需求 ID>，可写 <目录>，其他目录只读。交付可运行实现和 REPORT，报告逐项说明最终行为、命令原文、截图自检、真实数据与合成边界。

接口先按 <约定>，未知依赖只在 tests/ 注入明确标记的桩。不要复制历史作品、素材、地址、个人资料；用户素材放项目 assets/ 并记录许可。

共享服务器：只用分配的本地端口，记录 PID，只结束自己进程；不要修改系统代理、服务管理器、站点目录或他人工作缓存。重任务限制并发与磁盘占用。

测试默认浏览器策略，不放宽自动播放；受限数据缺失明确 SKIP。先测量再修，所有必要测试通过才交付。此任务范围中的部署/提交/推送权限：<明确写出>。未经授权不要执行额外外部动作。

音乐视频任务：先读 directing/01-mood-first.md 与 01b-imagery-translation.md，先意境书/转译表，后分镜与代码。主画面使用 three.js 三维；SVG/Canvas 可用于叠加层与排版。每道 G1/G1b/G2G3/FINAL 都要停下产出证据，等待独立审核结论；自审不算，FAIL 不得继续下一关。独立审核由编排者按已有授权安排另一会话或人类；不擅自开启并行。逐关使用 REVIEW-music-video.md，保留失败证据。


执行预算：每条命令必须带超时（例如 `timeout 120s npm test`），长渲染明确上限与进度检查，超时保留日志。大文件先 `wc -l` 和 `rg -n`，再按行读取，每次不超过约 200 行，单次输出预算 8000 tokens；改动先看 `git diff --stat` 再按模块看 diff。图像先审联系表，只有疑点才打开单张原图；不把整曲帧、源码或日志塞入上下文。上下文余量低于 20% 时先写项目 `docs/CHECKPOINT.md`，包含约束、接口、已完成、失败证据和下一条命令，再恢复执行。

任务端口：只监听 `127.0.0.1:39920–39929`，占用则换空闲端口，不结束占用者。启动立即记录自己持有的 PID，finally 按 PID 结束并等待退出；禁止按进程名批量清理。单浏览器、两线程起步，输出预估设硬上限。

编排者停滞看门狗：项目源码 60 分钟无变化即终止该任务的自有进程，等待退出后带 `docs/CHECKPOINT.md` 重启；日志、缓存和渲染输出增长不算实现进展。`tools/watchdog.mjs` 以 `--idle 3600 --timeout 7200 --restarts 1` 执行受监控命令，通过 `SCENE_RESTART_CONTEXT` 传入检查点；命令入口须读取该文件，不可仅传路径而忽略内容。连续停滞保留诊断并报告，不无限重启。看门狗不授予并行权限。

设计与实现分工：设计文档（SET 组件表、NEW-HARD 配方、逐镜物料清单）由设计者写满并先过 `npm run qa:brief`；实现者只在文档的“回填”一节写结果，设计缺口写成请求并按配方的降级方案继续，不自行补设计。引擎已有能力（相机路径与手持、天空、雾、水、粒子、后期、署名）只用引擎函数与参数，清单见 engine/README.md“已有功能清单”；每轮 `npm run qa:reimplement` 0 条，有相机运动时 `npm run qa:camera` 每镜 PASS。


迭代轮次与会话纪律（难件、检查台、场景每一轮都适用，规则见 playbook/15-iteration-protocol.md）：
- 一轮一会话：本会话只做本轮，交付后停下；导演审片、改配方后由新会话开下一轮。每件最多 3 轮，第 3 轮仍不过按配方 ⑧ 降级并在回填里写明。
- 附图：本任务附有导演审过的上一轮联系表 <附件路径>。先用几句话描述你在附件里看到的问题，再开始改；会话内读图不可用时明确说明，改用数值剖面 / ASCII 亮度图，并写进 LOG。
- 联系表自检：生成后先算平均亮度与每格方差（全黑、全白或空格 = 生成失败），再读图确认每格有画面，才算交付。
- 观感指标按配方 ⑥ 的成对边界与测量口径测（本构件掩码、排除邻件、边界腐蚀、1920 宽 + 锁颗粒、掠射采样贴表面）；不为过检改阈值或掩码，度量做不到时在回填写请求并附推算。
- 认为是引擎缺陷时不要改引擎：写出复现步骤与证据，交导演安排另一会话独立复现。
- 检查台/调试页的 URL 参数先 grep 引擎读取查询参数的位置，不与引擎已有参数同名（建议加件名前缀）。
- 结束前按 PID 关闭你启动的所有服务与浏览器，汇报写“已关闭 PID …”；不按名字杀进程。被额度或超时切断时，下一会话按 LOG/CHECKPOINT 从断点续跑。

画面关卡：每一轮看图目录先跑 `npm run qa:picture -- --dir <本轮>`，全部 PASS 才交导演/审核；报告 `failed` 与 `px` 指出要改的区域。任何“已修复”的汇报必须附 `npm run qa:picture -- --dir <本轮> --compare <上一轮> --claim <检查项>` 的结果，⑥ 显示问题区域确实变化，否则视为未修复。修 ①条纹 先查几何与投影（竖面是否用了地面投影、雪丘是否竖壁、机位是否贴着大物体、图案长宽比），修 ②描边 先查遮罩相机与尺寸，修任何材质先确认程序缓存键与注入锚点生效，再调参数。人物只用人物组件，雪/冰/夯土只用 kits/materials，不改组件、不另写同类 shader。规则见 playbook/14-picture-gate.md。
